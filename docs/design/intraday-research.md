# 微台日內研究與本地資料庫

日期：2026-11-15。公開 Fubon Web fork 的獨立研究功能，不取代上游私有 `BacktestCore` 全功能實作。

## 操作與資料

「新增面板 → 策略回測」在公開 Web 版開啟本面板。選 TMF／MXF／TXF、具體交割月份及已完成日期，每次最多 31 天；預填股票與權重是明確標示的固定假設範例。下載後可按「只讀本地資料庫」，不再次請求券商。行情權限、連線、空資料與輸入錯誤會顯示，沒有以展示資料替代下載失敗的路徑。

- `demo`：可完整操作流程，歷史為合成資料，結果持續標示合成來源。
- `paper`／`sandbox`／`live`：透過該模式行情客戶端查詢歷史；此功能不呼叫下單、撤單或改單。是否能取得特定月份與股票仍受券商行情權限及實際資料限制。
- 期貨查詢使用 `product`＋具體 `contractMonth`，可查已到期月份，無須先以即時 ticker 解析。沒有使用連續月價差拼接損益。
- Fubon 的分鐘起點標籤轉為分鐘終點，保存真實 UTC epoch 秒；前端以 Asia/Taipei 顯示。研究資料不使用圖表的牆鐘編碼。
- 不接受負量、無效 OHLC、分鐘內秒數或重複時間衝突；官方無成交的全空 OHLC／零量分鐘保留為缺口，不前補／後補價格，落在必要視窗時會排除該日。

官方欄位：[期貨歷史 K 線](https://www.fbs.com.tw/TradeAPI/docs/market-data-future/http-api/historical/candles/)、[股票歷史 K 線](https://www.fbs.com.tw/TradeAPI/docs/market-data/http-api/historical/candles/)。

## SQLite

位置：目前 worktree 的 `server/.research.sqlite3`（已忽略 Git）。WAL 模式；每次操作有交易與明確關閉連線。

| 表 | 用途 |
|---|---|
| `research_bars` | 原始 1 分 K，複合主鍵按資料來源、股票／期貨、代碼、月份、盤別、時間索引 |
| `research_ranges` | 成功查詢的覆蓋範圍；重新下載會原子替換該範圍、使重疊覆蓋紀錄失效 |
| `research_weights` | 固定假設籃子、版本日期與本機取得時間 |
| `research_datasets` | SHA-256 版本與壓縮不可變資料副本，可重現當次計算 |
| `research_signals` | 版本下每個 5 分決策時點的權值股近 5 分加權變化、期貨價與缺資料名單；主鍵支援最新時點查詢 |
| `research_runs` | 資料版本、當次設定、來源、比較結果、逐筆明細及保存時間 |

`/research/latest` 只讀該版本的已保存決策時點，沒有網路或全歷史重算，並回傳實際本地耗時。它是**歷史資料快速判讀**，尚未接即時行情持續入庫；畫面不得呈現為目前可交易的即時訊號。

固定假設權重無法證明當時已可取得，來源分類始終為探索性假設；版本日晚於回測開始日另加提醒。逐日官方歷史成分、權重與公布時間仍是後續資料工作，不得以今天的名單冒充歷史投資範圍。

## 第一個可重現比較

目的是檢驗權值濾網的增益，不進行自動調參：

1. 共同現貨時段固定 09:00 起；首 15 分鐘建立期貨高低區間。
2. 09:20–13:10 的 5 分收盤，由區間內首次穿越區間邊界時產生多／空候選。
3. 下一根 1 分 K 開盤加入不利滑價，單一持倉、不加碼，同方向每天最多成交一次。
4. 固定點數停損與 R 倍數停利；目標距離向外取整至 1 點，停損與滑價只能輸入整點。
5. 跳空穿越停損時按不利開盤價估計；同分鐘停損／停利都碰到且無法判先後時，採停損。兩邊費用、按名目金額計算的稅及滑價均納入。
6. 13:20 收盤模擬退出。缺少 09:01–13:20 任一分鐘的期貨日整天排除，以免缺段掩蓋停損。
7. 濾網版另要求各假設股票於決策時間與五分鐘前都有資料，且 `sum(weight × 5m return)` 與進場同向。
8. **兩組都要求同一套股票資料可用**，因此「基準」是共同資料樣本的消融對照，不是完整期貨單獨策略。報告缺資料時點與排除日。

輸出成本後損益、平均每筆淨損益、平均贏／輸、獲利因子、分鐘收盤估值的最大回撤、交易筆數與勝率，逐筆保留原因；平均值只描述樣本，無虧損樣本不計獲利因子，分鐘回撤可能低估根內風險。沒有排隊、部分成交、實際行情到達延遲、保證金或市場衝擊模型。回測結果本身不構成實盤獲利證明。

## 接續驗證

其他候選見 [策略研究](../research/intraday-strategy-candidates-2026-11-15.md)。先固定小量候選與參數，再按時間做樣本外比較；保存全部嘗試，避免只選最佳歷史圖。虛擬貨幣的方法需要重新處理 24 小時市場、資金費、場地差異與交易成本，不能直接把其績效搬到微台。

驗收以純引擎手算案例、SQLite／HTTP 測試及隔離瀏覽器流程分開記錄。合成 UI 驗收與真實富邦歷史行情下載是不同證據。真人試用沿用既有 Passkey；不複製測試 authenticator 至正式資料庫。
