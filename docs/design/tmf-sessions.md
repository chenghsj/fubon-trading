# 微台完整日盤與夜盤研究／Paper

日期：2026-11-17。

本次需求：以微台夜盤歷史行情訓練 LightGBM、比較成本後損益與最大回撤，接入 Paper 自動交易；另涵蓋完整期貨日盤 08:45–13:45。保留舊的現貨重疊策略，避免舊資料被當成全天期貨樣本。

官方來源：[期交所微台規格](https://www.taifex.com.tw/cht/2/tMF?menuid1=12)、[盤後交易制度](https://www.taifex.com.tw/cht/4/aHIntroduction)。到期月份最後交易日日盤提早收盤、且沒有當日夜盤；新完整盤計畫拒絕選用開盤當日到期的月份。歷史缺分鐘的盤排除，另顯示日期。

## 日期、資料與模型

- 富邦歷史 API 的 `from`／`to` 是官方交易日，盤後交易歸屬下一交易日。必須保留回傳 timestamp，不以查詢日期減一天推算開盤日；例如週一查詢可能回傳週五15:00至週六05:00。資料保存官方查詢區間，另外顯示實際開盤日期範圍。[富邦歷史 K 線文件](https://www.fbs.com.tw/TradeAPI/docs/market-data-future/http-api/historical/candles/)
- 資料完整性檢查完整期貨日盤300根、夜盤840根已收盤1分K；全空OHLC／零量分鐘保留為缺口，不補價格。缺分鐘、重複衝突、同盤多契約月份不得冒充完整盤。
- 日夜盤原版模型使用期貨本身的8個特徵：5／15分鐘報酬、ATR／價格、開盤區間／價格、突破距離／ATR、K棒實體比例、相對量、盤內進度。新版多週期模型再加入18個特徵，共26個。資料與ATR以當盤開盤重設，夜盤不依賴已休市股票的同步行情。舊 `cash` 原版保留12特徵，多週期則為30個。
- 每個實際開盤日的整盤按60/20/20分訓練／驗證／測試；夜盤跨午夜不分組，purge依下一組首盤開盤時間。固定分類模式使用50輪、depth3、7葉、seed42與0.5門檻，不依封存測試調參。
- 標籤與績效沿用下一根開盤、不利滑價、單口費稅、ATR停損、2R及20分鐘退出。兩種新模型分開保存資料／規則／特徵／程式hash，禁止日盤模型套用夜盤。
- 正常及每邊額外2點滑價情境比較同樣事件序列；保存淨損益、分鐘收盤估值最大回撤與逐筆成交。沒有本金分母，不以金額損益宣稱報酬率；分鐘回撤可能低估分鐘內風險。
- 無資料平日尚未逐一核對官方休市，完整性與數值比較通過不等於來源／統計／獲利驗證。

## Paper 接入

- 僅新增 Paper 夜盤；Sandbox保留日盤、Live不開放自動交易。Broker與Gateway兩層均保留限制，Paper委託只能進入本機帳簿。
- 計畫的日期明確為「實際開盤日」，夜盤於15:00所在日期建立；午夜不重設進場額度、部位、損失預算或模型。資料庫計畫鍵包含模式、日期、帳戶與策略盤別，日夜不互相覆寫。
- 上方交易模式可用「自動」按商品解析目前盤別，或手動指定相符盤別；策略仍只執行設定的單一日／夜盤。啟動與每次執行均核對商品盤別，若自動盤別已切換則停止送出；手動切換設定前仍須停止策略、處理曝險後重新連線。
- 選本機模型會套用相同盤別、V2風控、成本、單口、每盤最多兩次意圖與1000元損失預算。下載／訓練不會自動啟動策略。
- 繼續使用新鮮報價、已收盤K棒、限價IOC、送出前保存意圖、權威成交對帳、未知結果不重送、心跳逾時停新倉與重啟後人工恢復。停損／停利及時間退出不依賴模型可用性。

## 依收益進行有限候選滾動研究

使用者補充要求：重點為成本後的可重複收益，不只完成一次fit。新增 `method=walkforward`，UI預設此研究方法，仍可保留固定分類對照。

- 限定6個候選：分類門檻0.4／0.5／0.6；成本後淨收益回歸門檻NT$0／50／100。其餘樹參數、停損停利、持有時間及成本不隨測試結果改動。
- 只在前80%日期內做三段expanding因果驗證，約以40%→53.3%、53.3%→66.7%、66.7%→80%作驗證區間；各fold只用其開盤前已完成的標籤。完整候選與失敗結果保存。
- 滾動門檻要求每fold至少5筆、一般及額外滑價情境均正收益，合計至少20筆。通過候選依「壓力淨利－0.5×一般最大回撤」排序；若皆未通過，同一排序只選出診斷版本，明示未通過，沒有正式採用資格。
- 固定候選後，最終模型僅fit前60%，報告另列20%驗證及最後20%測試；測試資料不參與候選排序。最終測試仍需通過成交數、一般／壓力淨利、相對基準與回撤門檻。
- 收益模型分數的單位為NT$，可為負值；分類分數才限制於0–1。即時Paper推論按保存的模型類型與門檻決定放行，未通過版本只供明示的實驗前測。
- 歷史區間上限放寬為1096天，但每次API請求仍最多31天，自微台2024-07-29上市日起可用。已看過的歷史測試不因更換模型變成全新樣本，仍需新日期Paper前測。

## 1m／3m／15m 多週期與每分鐘判斷

`TrainingRequest.feature_set` 支援 `base`（API相容預設）與 `mtf_1_3_15`（研究面板預設）。兩者都是一個LightGBM模型；資料快照可重用，不需分別下載3分或15分K。模型報告、原生特徵順序、程式hash及Paper設定都區分版本，不會自動替換既有計畫。

- 保留原版8／12特徵，按1、3、15分鐘順序各加入報酬、價格區間／收盤價、實體／區間、收盤區間位置、相對量、最近最多3根趨勢報酬，共18項。報酬與方向特徵依突破買賣方向標準化。
- K棒從實際當盤開盤時間錨定，逐根OHLCV聚合，只有整根收盤才納入。例如日盤09:05判斷時，3分K最近一根截至09:03，15分K截至09:00，不能使用09:06或09:15才完成的資料。相對量均值使用最近最多5根含當前完整K；盤初至少1根，趨勢使用最近最多3根。盤初暖身仍至少20分鐘，絕不借用另一盤資料。夜盤午夜保持同一盤。
- 多週期模型每1分鐘收盤判斷開盤15分鐘區間的新穿越，對比前1分鐘收盤；原版維持每5分鐘、對比前5分鐘收盤。這是事件頻率與特徵共同變更，兩版績效差異不能只歸因於新增特徵。
- 判斷頻率保存於模型policy；`AutoConfig.decision_minutes`由模型設定固定為1或5，無模型不得切為1。訓練事件、即時推論、啟動不追補訊號及送出前的當分鐘訊號核對都採相同頻率；移除模型則恢復5分鐘。
- 單口、每方向每盤最多一次意圖、費稅滑價、ATR風控、20分鐘持有上限與退出時刻沿用。增加判斷頻率不代表增加下單額度或略過風控；沒有符合條件時仍不下單。
- 重新跑同樣6候選／三段滾動研究，原版與新版分別保存全部結果；最後測試不選擇特徵或頻率。既有測試歷史已看過，這次比較仍是歷史研究，不能當作新日期Paper前測。
