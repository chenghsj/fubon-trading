# 區間與順勢第二輪：先固定方法，再比較結果

本輪目標是改善成本後報酬，不承諾可將歷史規則調成未來一定賺錢。原 V3、舊模型、原失敗結果全部保留；本輪程式只有離線研究入口，沒有加入券商或自動下單路徑。候選家族在第一次跑新績效前固定如下。

## 開發資料的虧損來源

以下僅讀上一輪的 development 前60%保存結果：

| 盤別／分支 | 筆數 | 成本後淨額 | 平均贏單 | 平均輸單 | 期限退出筆數 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 日盤／區間 | 171 | -19,914 | 159.1 | -302.9 | 50 |
| 日盤／順勢 | 152 | -9,592 | 295.1 | -277.9 | 96 |
| 夜盤／區間 | 341 | -31,641 | 172.4 | -355.4 | 68 |
| 夜盤／順勢 | 324 | -23,880 | 342.9 | -277.2 | 195 |

區間中線目標相對停損與成本可能太近；趨勢方向即使有小幅價格優勢，20分鐘期限與摩擦也可能抵銷它。這是待驗證解釋，不能由上表推論改出場就會獲利。

## 固定候選

共同保留15分ER8（盤整<=.25／趨勢>=.55）、135分鐘當盤暖身、先前已收盤3分背景、1分收盤觸發、30點最低停損、單口、每方向每盤一次、最多兩次意圖、1000元預算、10點追價限制與原盤別截止。來回費稅與滑價後，區間目標淨收益至少等於估計停損風險；順勢仍使用2R名目目標。每邊費用NT$20為假設，每邊滑價2點。

| 固定識別 | 區間目標／觸發 | 順勢觸發 | 最長期限 |
| --- | --- | --- | ---: |
| quality_20 | 原下／上20%返回，中線；淨報酬／風險>=1 | 原18分鐘結構突破 | 20分 |
| quality_40 | 同上 | 同上 | 40分 |
| pullback_40 | 同上 | 拉回確認 | 40分 |
| pullback_60 | 同上 | 拉回確認 | 60分 |
| far_edge_pullback_40 | 原返回觸發；買方目標區間80%、賣方20% | 拉回確認 | 40分 |
| bands_pullback_40 | 前20根3分收盤均值±2母體標準差返回，目標均值 | 拉回確認 | 40分 |
| far_edge_breakout_40 | 原返回觸發；另一側80%／20%目標 | 原突破 | 40分 |

「拉回確認」使用**不含訊號分鐘**的前5根完整3分收盤均值；上行15分盤勢且該均值比前一個5根均值上升，前一分收盤<=均值、本分收盤>均值且本分低點觸及均值才買入；空方鏡像。波動帶結構停損取前20根3分低／高點外0.25 ATR，其餘區間沿用12根通道；確認成交後保護價計算沿用共用函式。候選名稱不代表已核准執行。

## 選擇與評估規格

1. 日／夜盤分別依已保存完整 opening-date 60／20／20切分。本輪選擇只產生前60%的事件，使用全期間30–40%、40–50%、50–60%三個連續區塊；沒有將後40%傳入選擇函式。不存在新模型fit或特徵標準化。
2. 每個區塊至少20交易、一般與每邊額外2點滑價均正淨額；三塊合計的區間、順勢各至少15筆且壓力淨額為正，才列為 development eligible。先選eligible，再按最差區塊壓力淨額、總壓力淨額減0.5倍最大一般分鐘收盤回撤排序。全數不合格則只保留最佳診斷候選，不能稱通過。
3. 保存全部7候選與original_v3參照的三區塊交易、數量、均值／中位數、分支、日期損益、回撤及失敗。凍結候選、資料ID、規格及原始碼SHA256後，由另一個CLI階段只評估選定候選與原版的後20%驗證及後20%重用歷史測試；候選／規格／程式改變則拒絕沿用凍結檔。
4. 每次列一般、額外2點滑價、延後一分鐘三場景的**不同交易數**。延後用第二根未來分鐘開盤，重新檢查價格／觸發／空間／預算，仍受原訊號起算20／40／60分鐘及當盤退出期限限制；實際入場已逾last-entry時拒絕。延後場景是假設成交延遲的價格敏感度，不等於現有V3執行行為：現有執行器跨分鐘會取消過期訊號，研究不放寬它。
5. `maxDrawdown`依分鐘收盤估值與實現退出價計算，沒有逐筆最低浮虧／撮合排隊證據。即使較長期限提高某段淨利，也需檢查滑價、延後、去除最佳開盤日、兩分支與回撤，不能只報最佳總額。
6. 所有歷史都已參與前輪研究，所以後段仍標記**重用歷史**。原正式採用目標（至少300日期、最後60日期鎖定、最後至少100交易及各分支30）不因本輪比較而降低；本輪`adoptionAllowed`、`executionEnabled`始終false。通過開發比較仍需新日期Paper前測，不自動啟動策略。

## 來源與重現

TMF每點NT$10、1點最小跳動與交易時段依[期交所契約規格](https://www.taifex.com.tw/cht/2/tMF)。回測反覆挑選造成的過度擬合問題參考[Bailey等原始研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)；本輪七個參數假說並非該論文驗證的獲利規則。其他來源與原假設見[第一輪規格](tmf-regime-strategy-2026-11-18.md)。

```sh
uv run --directory server --extra learning python ../scripts/refine-regime.py --stage development
uv run --directory server --extra learning python ../scripts/refine-regime.py --stage evaluation
```

研究直接唯讀已保存SQLite快照、不建立券商連線；有執行中策略、持倉或待確認委託即拒絕。完整結果保存於`.fubon-dev/reports/refinement-v1-verified/`，不覆寫舊紀錄。獨立QA發現首次凍結少列品質篩選原始碼與精確日期切分，已補齊並以同一候選家族重跑；首次無已確認洩漏，原紀錄保留於`refinement-v1/`。實際結果在跑完後另附，不能修改上方家族來追逐後段獲利。

## 規則失敗後固定的學習層

七個規則候選均未通過上述開發門檻，沒有更改ER、成本或門檻把它們變成合格。再固定一個有界學習比較：同七組事件，沿用當刻28個特徵，各訓練單一LightGBM成本後淨收益迴歸，預估淨額門檻固定NT$0／50／100，合計21個組合；沒有使用後段結果挑選或調整模型。

參數固定100輪、7葉、最大深度3、learning_rate .03、葉最少30事件、L2懲罰10、seed42、兩執行緒。每個開發區塊只fit其之前的已結束標籤，從原先未使用的最早30%資料開始訓練；至少60合格事件才fit。標籤為相同進出場、費稅、滑價、預算政策下的未來淨額；特徵不使用下一根開盤或標籤結果。

選擇沿用三區塊與雙分支門檻，另要求三塊延後場景也全部正淨額。全部21個組合均保存；無合格時保留診斷候選。只用前60%fit最終原生模型，將其雜湊、套件版本、資料與精確分割凍結後，再由獨立evaluation階段讀後40%。本輪沒有將模型接入自動交易，執行／採用旗標始終false；失敗後不再擴張這輪參數家族追逐後段獲利。

```sh
uv run --directory server --extra learning python ../scripts/refine-regime-model.py --stage development
uv run --directory server --extra learning python ../scripts/refine-regime-model.py --stage evaluation
```

模型與完整比較保存於`.fubon-dev/reports/refinement-model-v1/`。這21個選擇也算入累計研究嘗試，不能把最好的一個當作只有一次事前假說的證據。
