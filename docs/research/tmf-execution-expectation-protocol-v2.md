# 執行情境期望模型與資格檢查修正 v2

2026-11-18。Paper維持停止。這次修改既有模型訓練／預測／資格檢查，
用同一批訊號與資料做修正前後對照，不增加策略候選。

## 已重現的問題

1. 原本每個動作先取正常／壓力／延遲的事後最低淨利，再回歸。
   這估計 E[min(Y_s)|X]，不是最差固定執行情境的條件期望 min(E[Y_s|X])。
   兩筆相同特徵動作，正常收益600／−300、壓力580／−320、延遲−300／600：
   各情境期望150／130／150元，逐筆取低卻平均−310元。舊程式符合舊spec，
   問題是原目標比本次需要的穩健期望過度悲觀，不能宣稱它是舊規格實作錯誤。
2. 一般模型丟掉下一分鐘不符合入場條件的機會，與訊號時尚未知能否執行的
   現金流目標不一致。256次機會、有一半不執行，舊fit只剩128筆。
3. calibration_check({})、final_check({})可回傳通過；NaN及正無限大亦可繞過
   <=0比較。這是資格檢查缺陷，校準、發展選擇與最終檢查都需拒絕。

先以test_execution_expectations.py執行重現，5 failed／1 passed，0.13秒；
修正後才跑真實歷史。這些toy案例不是實際交易獲利證據。

## 修正方式與固定對照

- 一般模型預測正常執行的機會現金流；穩健模型分別訓練正常／壓力／延遲三個頭，
  推論後才取三個條件平均預測的最低值。未執行皆記0，三個頭採完全相同fit機會。
- 直接用NTD成本後現金流訓練，移除淨利／風險標籤再乘風險的轉換；
  新增訊號時已知的plannedRiskNTD作第55個模型特徵。其餘54個訊號特徵保持不變。
- Ridge標準化只在fit段學得；每頭相同取樣、權重、參數與日期，校準後不refit。
- 新模型保存單位、完整特徵順序與情境頭，缺任一頭即拒絕。舊單頭模型仍按原風險單位
  讀取，只供重現基準；禁止將新NTD輸出再乘一遍風險。
- 校準必須有正常／壓力／延遲，最終必須有驗證／已重用歷史測試期；
  成交數、淨額、去最佳日及分支指標必須完整、有限且數量合法。空、缺漏、NaN、Inf
  不得通過，選擇器也不得讓無效排序數字晉升。

四個既有模型變體、兩閾值0／30、三範圍與三純規則基準保持每盤27政策。
預算1000、費20元／邊、滑價2點／邊、額外滑價2點、晚一分鐘、進場與退出規則、
校準及資格成交數等門檻完全沿用[前一規格](tmf-structured-protocol-v1.md)。
資料仍為530完整日盤／395完整夜盤，日期60／20／20，發展三折30–40／40–50／50–60%。
最近120日變體及每前綴80／20 fit／校準也不變。

凍結後才評估後40%。每個修正前原生模型都重新載入，用原風險單位推論，
完整重播所有27政策的兩期三情境，結果必須逐項等於先前保存紀錄，否則停止比較。
新版本保存parentFrozen、資料、模型、特徵、套件與程式雜湊，拒絕變動訊號／成本／成交
程式後仍稱為配對。全部新結果及未通過原因保存，不覆寫舊版。

這估計最差固定執行情境的條件平均，不是每筆最差損失、尾端損失保證或可信下界；
未執行0只代表此OHLC回放的admission拒絕，不是實際IOC成交率。
盤中額度與等待機會成本仍由完整序列回放處理；所有日期已被看過，
不能把新正收益當作全新樣本外或未來獲利保證。

L2目標及Ridge依據見[LightGBM官方參數](https://lightgbm.readthedocs.io/en/stable/Parameters.html)
與[Ridge官方文件](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html)。
